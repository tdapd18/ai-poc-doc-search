# 개인 Windows PC용 실제 공유폴더 검색 — 분석·계획서

기준: `main` (8423c2f). 이 문서는 구현 전 분석과 계획이며, 구현 결과는 문서 끝의 "구현 결과"에 이어 기록한다.
**원칙**: 회사 자료를 외부(Claude Code·외부 AI)로 보내지 않는다. 이번 단계는 **합성 데이터로만** 구현·검증하고, 실제 회사 PC/공유폴더 연결 테스트는 보안 승인 후 별도 수행한다.

## 1. 현재 구조 요약 (재사용 가능성 관점)

```
Connector(fetch_all) ─▶ SyncManager(해시 비교) ─▶ Indexer(SQLite: documents/chunks)
                                                  ▲
  AccessController.can_access(user, doc) ◀── SearchEngine / AnswerGenerator / History  (권한 판정 호출 지점이 한 곳으로 모여 있음)
```

- 검색 엔진·색인·동기화·UI·캐시 재검증은 **Document 스키마와 `can_access` 인터페이스에만 의존**한다 → 대부분 재사용 가능.
- 현재 공유폴더는 `Share.unc_root`(표시용 문자열) ↔ `local_dir`(가상 폴더) 매핑이며, 모든 파일을 매번 전부 읽고(전체 재수집), 메타데이터는 `---` 머리말 또는 `.meta.json`, 권한은 파일 안의 `allowed_*` 목록이다.

## 3. 핵심 설계 결정

1. **권한 = 운영체제가 판정**: 앱은 사용자 PC에서 사용자 계정으로 실행되므로, 파일을 *실제로 열 수 있는지*를 권한의 근거로 삼는다. (`os.access`는 Windows에서 ACL을 반영하지 않아 사용하지 않음.) ACL을 앱이 직접 해석·복제하지 않는다.
2. **2단계 검증**: (a) 대량 필터는 색인 시점에 읽을 수 있었던 문서 집합(스냅샷)으로 빠르게, (b) 사용자에게 보이는 모든 지점(결과 행, 미리보기, AI 근거, 이전 답변, 캐시 적중)은 **그 순간 파일 열기로 재검증**. 삭제·권한 회수·공유 불가면 숨김.
3. **색인은 계정별 로컬 파일**: 홈 폴더(`%LOCALAPPDATA%`) 아래 개인 색인. 다른 계정으로 실행되면 색인을 폐기. 본문은 로컬 DB에만 저장(암호화는 후속 과제 — DPAPI 등).
4. **두 가지 색인 수준**: `metadata_only`(파일명·경로·형식·수정일·크기만, 파일 내용 미열람, 열기 시도는 권한 확인용으로만) / `full_text`(본문 추출). 본문 모드는 **보안 승인 확인 기록** 없이는 활성화되지 않고, 모드 전환 시 색인을 초기화한다(절차적 통제이며 기술적 강제는 아님 — 사용자가 설정 파일을 직접 고칠 수 있음을 문서화).
5. **자동 메타데이터**: 문서 ID = 정규화 UNC 경로의 해시, 제목 = 문서 속성 제목 또는 파일명, 날짜 = 파일 시각, 버전 = 파일명 패턴(없으면 `-`), 부서 = 상위 폴더, 분류 = 규칙(키워드) 추정. `.meta.json`/머리말이 있으면 우선(데모 호환).
6. **안전한 변경 처리**: 수정 → 지문 불일치 시 재추출(그 전에는 "원본 변경됨" 표시); 삭제/접근 거부 → 조회 시 즉시 숨김, 동기화 시 색인·조각 삭제(fail-closed); 일시 오류(잠금·네트워크) → 기존 색인 유지·조회 시 숨김·재시도; 공유 접근 불가 → 해당 공유 색인 유지하되 숨김·경고.
7. **실제 SMB 접속 코드는 `LocalFS`가 OS의 UNC 지원을 그대로 사용**한다(Windows에서 `\\서버\공유\...`를 파일 API로 읽음). 자격증명을 앱이 저장·전달하지 않는다. **이 경로는 Linux 개발 환경에서 실행·검증할 수 없으므로 합성 파일시스템으로 대체 검증**하고, Windows 실기 검증은 보안 승인 후 체크리스트로 수행한다.

## 5. 테스트 계획 (합성 데이터만)

**합성 Windows 공유 픽스처**(테스트 시 임시 폴더에 생성, 모두 가상 내용): 한글·공백·특수문자 파일명, 대문자 확장자, 깊은 폴더, 동일 파일명 다른 폴더, DOCX(제목·표), XLSX(날짜·퍼센트·병합·숨김 시트), PPTX(숨김 슬라이드·노트), PDF(Flate·ToUnicode·객체 스트림), CSV(UTF-8 BOM·CP949·세미콜론), TXT(CP949), 머리말 없는 MD, 임시 잠금 파일(`~$`), `Thumbs.db`, `desktop.ini`, 레거시 `.doc/.xls`(OLE), 암호화 DOCX(OLE), 손상 파일, 0바이트, 한도 초과 파일, 접근 거부 폴더/파일, 순회 중 사라지는 파일, 읽기 중 변경되는 파일.

| 영역 | 검증 항목 |
|---|---|
| 파일시스템 | UNC→로컬 매핑, 오류 분류(거부/없음/불가), 확장 경로 변환, 케이스 비구분 ID |
| 권한 | 접근 거부 문서는 색인·검색·미리보기·AI 근거·이력·캐시에서 제외, 권한 회수/복구, 공유 불가 시 숨김, 다른 계정 색인 폐기 |
| 자동 색인 | `.meta.json` 없이 색인, 메타데이터 도출 규칙, 제외 패턴, 임시/시스템 파일 제외, 미지원/손상/암호화 보고(건수) |
| 추출기 | DOCX/CSV 신규, 인코딩, PDF·Excel·PPT 개선 케이스, 경계·방어 |
| 보안 모드 | 메타 전용에서 파일 내용을 읽지 않음(읽기 호출 0 검증), 본문 승인 없이 전환 불가, 전환 시 초기화, 본문 범위 안내 |
| 동기화 | 수정·삭제·이동·권한 변경·일시 오류·공유 불가, 증분(변경 없는 파일 미재읽기), 읽기 중 변경, 캐시·이력 무효화 |
| 설정 화면 | 등록 검증 → 연결 테스트 결과 → 사전 점검 → 색인 생성 흐름(AppTest), 오류 안내 |
| 회귀 | 기존 141건 전부 유지 |

미검증(보안 승인 후 별도): 실제 Windows UNC 읽기, 실제 NTFS/AD 권한 반영, 네트워크 지연·VPN 단절, 대용량(수십만 파일) 성능, 실제 업무문서 추출 정확도.
